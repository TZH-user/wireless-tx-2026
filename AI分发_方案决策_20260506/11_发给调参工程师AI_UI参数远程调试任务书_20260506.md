## 6. 验收标准

### 6.1 链路验收

每个 case 必须满足：

- 日志命中新 `fw_id`。
- 日志命中 `sigdet_final`。
- 日志存在 `mod` 扩展字段。
- 有效 `mod` 行不少于 10。

否则不得进入参数结论。

### 6.2 模式显示验收

以 `stable` 字段作为 UI 显示代理：

- `stable` 多数应等于目标模式。
- `conf` 应有可解释趋势，不能长期为 0 或乱跳。
- 对 ASK/FSK 的瞬时跳变，只要 `stable` 能压住，UI 认为可用。

### 6.3 参数估计验收

当前参数估计是第一版估计值，不要求精密仪表级准确。

最低要求：

- AM 10kHz：`rate` 应接近 10kHz，允许较大误差，但不得数量级错误；`depth` 应能反映 50% 调幅，不应接近 0。
- ASK 10kbps：`rate` 应接近 10k，`depth` 应明显大于 AM 小幅波动情况。
- FM 10kHz dev=75kHz：`rate` 应接近 10k，`dev` 应非零且量级接近几十 kHz。
- FSK 10kbps hop=20kHz：`rate` 应接近 10k，`dev/shift` 应非零且量级接近几十 kHz。
- PSK 10kbps：`rate` 应接近 10k 或能稳定反映跳变事件，`psk` 特征应明显。
- CW：`rate/depth/dev` 应接近低值，不能显示成明显调制。

如果某个参数估计出现数量级错误，允许你修改估计算法，但不能破坏模式分类。

## 7. 建议调试方式

### 7.1 优先用串口代理 UI

由于用户看不到屏幕，建议临时增加 UI 代理日志：

```text
ui,mode=<stable>,inst=<mode>,conf=<percent>,rate=<hz>,depth=<pm>,dev=<hz>,shift=<hz>
```

要求：

- 只在 `UART_MODE_LOG` 下输出。
- 建议 500ms 或 1000ms 输出一次。
- 不要淹没 `mod` 和 `sigdet` 日志。

### 7.2 不要立即上 FFT

本任务优先验证当前低成本估计。只有当 `rate/dev` 在多个 case 中明显数量级错误，且时域修正无效，再提出 Goertzel/小 FFT 方案。

优先考虑：

- 更合理的边沿去抖。
- 多块平均参数估计。
- 对 AM/ASK 使用包络二值化后的周期估计。
- 对 FM/FSK 使用 `dphi` 符号翻转和幅度均值。
- 对 PSK 使用相位跳变事件间隔。
