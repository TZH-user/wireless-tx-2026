## 2. 背景

当前载波扫频锁定逻辑中，最终频率 `final_hz` 同时用于：

- 屏幕显示载波频率：`estimated_carrier_hz`
- DDS/LO 实际输出频率：`current_lo_hz`
- 后续调制识别使用的 I/Q 数据生成

当前代码在锁定时会执行固定半步修正：

```c
final_hz = estimate_hz;
if (final_hz != APP_SIGDET_VALID_STOP_HZ)
{
    final_hz -= APP_SIGDET_FINE_STEP_HZ / 2;
}

estimated_carrier_hz = final_hz;
current_lo_hz = final_hz;
app_signal_detect_set_lo(final_hz);
```

当前 `APP_SIGDET_FINE_STEP_HZ = 50000UL`，所以通常会修正 `-25kHz`。

问题：调制参数识别依赖锁定后的 LO。如果 LO 与真实 RF 还有几十 kHz 残余差频，则 FM/FSK/PSK/CW 的参数估计和分类边界都会被污染。

## 7. 必须评估的策略

不要一开始就改代码大重构。先用日志和离线分析比较以下策略。

### 7.1 当前策略

```text
final_hz = current_estimate_hz - fine_step/2
```

优点：简单，已在前面测试中表现可用。

风险：如果 Vpp 曲线估计本身已经是中心点，再减半步会引入固定偏差。

### 7.2 不修正策略

```text
final_hz = current_estimate_hz
```

要求：用同一批 Vpp 曲线离线计算，如果不修正误差更小，则说明当前 `-25kHz` 需要取消或改为条件修正。

### 7.3 谷点优先策略

```text
final_hz = valley_step_freq
```

适用于：载波处 Vpp 最小的硬件响应稳定成立。

风险：如果谷点平台宽或噪声大，单点谷值会跳动。

### 7.4 有效边沿中点策略

```text
final_hz = (left_edge_hz + right_edge_hz) / 2
```

适用于：Vpp 曲线呈“低谷 + 两侧上升”，左右边沿可稳定找到。

风险：端侧 30/50MHz 可能一侧边沿不完整。

### 7.5 谷点邻域多点拟合/平均

候选：

- 取谷点及左右各 1 点，做加权平均。
- 取谷点附近 3 点或 5 点，做二次曲线拟合，估计谷底。
- 对低于阈值的连续区间取中心。

优点：比单点谷值稳。

风险：代码复杂度略增加，需要防止端侧越界。

### 7.6 锁定后微调策略

候选：

```text
锁定后在 final_hz 附近 ±N kHz 做小步短测，寻找 I/Q Vpp 最小或残余差频最小的位置。
```

本轮只评估，不优先接入。除非基线误差明显影响参数识别。
