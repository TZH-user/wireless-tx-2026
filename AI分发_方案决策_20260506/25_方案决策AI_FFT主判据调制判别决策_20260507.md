# 方案决策 AI：FFT 主判据调制判别决策

- 决策时间：2026-05-07
- 决策角色：方案决策 AI
- 适用工程：`D:\VSCodeCMAKEProject\Simple_wireless_IQ_demodulation`
- 前置约束：`22_方案决策AI_RF输入上限决策_20260507.md`
- 关联现状：`23_方案决策AI_载波锁定误差审查与基带频谱放行_20260507.md`

## 1. 总体结论

采纳新的调制判别主线：

- 载波锁定后，**以基带复数 FFT 特征作为主判据**。
- 现有 `app_mod_detect.c` 中的包络/相位/边沿统计，**不删除**，但降级为：
  - 家族内二次分流
  - 边界条件兜底
  - 参数估计补充

本次不采纳“只看 41 柱 UI 频谱条形图直接判别”的做法。

原因：

- 当前 `41` 柱、`5kHz` 步进的 UI 频谱适合观察，不适合直接做主分类。
- 真正用于判别的输入，应当是锁定后去均值的复数基带序列以及其完整 FFT bin 能量，而不是屏幕显示后的压缩柱值。
- 对 `PSK / FM / FSK` 来说，纯频谱仍不足以完全分开，必须保留少量时域相位跳变指标作兜底。

## 2. 现状判断

当前工程已经具备可复用基础：

- `app_baseband_spectrum.c` 已有复数 FFT 计算链路。
- 当前频谱摘要和 `41` 柱 UI 已可显示。
- `app_mod_detect.c` 已有：
  - `env_variation_pm`
  - `env_edge_pm`
  - `freq_activity`
  - `psk_jump_pm`
  - `positive_freq_percent / negative_freq_percent`
  - `dphi_hist_peak_count`

因此本轮不应推翻重写，而应改成：

- `FFT 特征先分家族`
- `旧时域特征后做家族内分流与兜底`

## 3. 采纳的架构

采纳以下结构：

```text
ADC I/Q block
  -> app_signal_detect        (载波锁定)
  -> app_baseband_spectrum    (复数 FFT + 频谱特征)
  -> app_mod_detect           (FFT 主判据 + 旧特征兜底)
  -> UI / UART
```

具体要求：

- `app_baseband_spectrum` 继续负责 FFT 和频谱特征提取。
- `app_mod_detect` 负责最终 `mode / stable_mode / confidence` 输出。
- 不允许让 `AdcTask.c` 直接写一套新的分类 if-else。
- 不允许直接从 `bars[41]` 做主分类。

## 4. 采纳的 FFT 输入配置

本轮采用当前可落地配置，不额外抬高复杂度：

- 输入：锁定后的 I/Q block
- 数据类型：复数基带 `I + jQ`
- 预处理：
  - 去均值
  - Hann 窗
- FFT 点数：优先复用当前 `256` 点复数 FFT
- 等效采样率：保持当前约 `200kHz`
- 有效判别频带：`-100kHz ~ +100kHz`

说明：

- `256` 点、约 `200kHz` 采样率时，bin 分辨率约 `781Hz`，对当前 `10kHz` 级 AM/FM/FSK/PSK/OOK 试验足够做第一轮主分类。
- 当前阶段不强制升到 `512` 点。若后续发现低速率 FSK/PSK 仍分不开，再单独开“FFT 分辨率升级”任务。

## 5. 采纳的频谱特征

判别时必须从完整 FFT bin 能量中提取以下特征，而不是从 UI 柱状值反推：

- `P_total`
  - `|f| <= 100kHz` 总能量，去掉无效/空块
- `dc_ratio_pm`
  - `|f| <= 1.6kHz` 的中心能量占比，单位千分比
- `near_ratio_pm`
  - `1.6kHz < |f| <= 6kHz` 能量占比
- `mid_ratio_pm`
  - `6kHz < |f| <= 20kHz` 能量占比
- `wide_ratio_pm`
  - `20kHz < |f| <= 60kHz` 能量占比
- `edge_ratio_pm`
  - `60kHz < |f| <= 100kHz` 能量占比
- `symmetry_pm`
  - 正负频能量对称性，建议按
    `1000 - 1000 * sum(|P(+k)-P(-k)|) / sum(P(+k)+P(-k))`
- `peak_count`
  - 有效局部峰个数，峰值阈值需相对噪底
- `dominant_pair_hz`
  - 最强对称峰对相对 `0Hz` 的偏移
- `pair_ratio_pm`
  - 最强对称峰对能量占非 DC 能量的比例
- `harmonic_ratio_pm`
  - 最强峰对的 `2f / 3f` 附近能量相对一阶峰对能量的比例
- `bw90_hz`
  - 包含 `90%` 频谱能量所需的对称带宽

## 6. 采纳的判别顺序

本轮采纳以下顺序：

1. `NO_CARRIER`
2. `CW`
3. 幅度家族：`AM / ASK`
4. 常包络家族：`FSK / PSK / FM`
5. 旧逻辑兜底

说明：

- 先判 `CW`，因为它最稳定，且会污染后续所有参数估计。
- 再判 `AM / ASK`，因为这两类在包络和频谱上最容易先分家族。
- `FSK / PSK / FM` 最后分，因为它们之间仅靠频谱容易交叠，必须接旧相位/边沿特征兜底。

## 7. 初版判定条件

以下条件作为 **V1 初版阈值** 采纳，允许后续基于新矩阵微调，但本轮先按此实现。

### 7.1 NO_CARRIER

判为 `NO_CARRIER`：

- 未锁定，或
- `carrier_present == 0`，或
- `P_total` 低于频谱有效门限

### 7.2 CW

判为 `CW`：

- `dc_ratio_pm >= 850`
- `bw90_hz <= 3000`
- `peak_count <= 2`

解释：

- 载波已锁定时，CW 的基带应主要集中在 `0Hz` 附近，只允许很小残余差频。

### 7.3 AM

先进入“幅度家族”前提：

- `env_variation_pm >= 180`

其后判为 `AM`：

- `symmetry_pm >= 850`
- `pair_ratio_pm >= 350`
- `harmonic_ratio_pm < 250`
- `bw90_hz <= 25000`

解释：

- AM 在锁定后通常表现为：
  - 明显 DC
  - 一对主要对称边带
  - 高频谐波不重
  - 总带宽不宽

### 7.4 ASK

先进入“幅度家族”前提：

- `env_variation_pm >= 180`

其后判为 `ASK`：

- `symmetry_pm >= 650`
- 且满足以下任一项：
  - `harmonic_ratio_pm >= 250`
  - `peak_count >= 4`
  - `bw90_hz > 25000`
  - `env_edge_pm >= 80`

解释：

- ASK/OOK 相比 AM，通常：
  - 边沿更硬
  - 谐波更多
  - 低频和高频扩展更宽
  - 包络边沿统计更重

### 7.5 FSK

进入“常包络家族”前提：

- `env_variation_pm < 180`

其后判为 `FSK`：

- `dc_ratio_pm <= 350`
- `pair_ratio_pm >= 450`
- `dominant_pair_hz >= 2000`
- `psk_jump_pm < 80`

解释：

- FSK 需要看到明显离开 `0Hz` 的主峰对或双频偏结构。
- 同时不应出现很强的 180 度相位翻转特征。

### 7.6 PSK

进入“常包络家族”前提：

- `env_variation_pm < 180`

其后判为 `PSK`：

- `psk_jump_pm >= 120`
- `symmetry_pm >= 700`
- `pair_ratio_pm < 450`
- `bw90_hz >= 3000`

解释：

- PSK 频谱常以 `0Hz` 为中心扩展，但不应表现成稳定双峰对。
- 真正关键仍是相位跳变指标，因此本轮规定 `psk_jump_pm` 为 PSK 必要条件，不允许仅凭 FFT 判成 PSK。

### 7.7 FM

进入“常包络家族”前提：

- `env_variation_pm < 180`

其后判为 `FM`：

- `symmetry_pm >= 750`
- `bw90_hz >= 5000`
- `pair_ratio_pm < 450` 或 `dominant_pair_hz < 2000`
- `psk_jump_pm < 120`

解释：

- FM 应表现为以 `0Hz` 为中心的对称展宽或多边带结构。
- 不能表现成典型双峰 FSK，也不能带有很强 PSK 相位翻转。

## 8. 兜底规则

采纳以下兜底策略：

- 如果 FFT 主判据没有任何一类满足，则退回当前 `app_moddet_classify()` 旧逻辑。
- 如果 FFT 与旧逻辑冲突：
  - `CW` 以 FFT 结论优先
  - `AM / ASK` 家族内，允许旧 `env_edge_pm` 参与二次裁决
  - `PSK / FM / FSK` 家族内，允许旧 `psk_jump_pm / freq_activity / dphi_hist_peak_count` 参与二次裁决

不采纳“FFT 与旧逻辑冲突时简单多数投票”的做法。

原因：

- 旧逻辑和新 FFT 逻辑不是独立观测器，直接投票会掩盖边界错误。
- 本轮应坚持：`FFT 先给家族，旧逻辑只做家族内裁决`。

## 9. 参数识别与调制判别的关系

本轮只决定“调制类型主判据”改造，不同时承诺参数识别已经自动跟上。

采纳以下关系：

- `mode` 先由 FFT 主判据给出
- 参数识别继续沿用当前：
  - `AM / ASK` 用包络类指标
  - `FM / FSK` 用现有频率活动与频偏估计
  - `PSK` 用相位跳变相关估计

后续如果 `mode` 稳定改善，再单独开“参数估计跟随 FFT 家族改造”任务。

## 10. 实现边界

必须遵守：

1. 不改 ADC/DDS 底层。
2. 不改 `APP_SIGDET_DDS_CHANNEL = 0U`。
3. 不使用 `RF > 1.5VPP` 数据调阈值。
4. 不从 `41` 柱 UI 值直接判别。
5. 不在 `AdcTask.c` 里堆新的大段分类逻辑。
6. 必须保留旧逻辑兜底，不能一次性删除旧调制识别。
