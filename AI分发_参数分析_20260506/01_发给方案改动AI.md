# 发给方案改动 AI

## 1. 你的职责

你负责确定本轮采用哪套参数/算法路线，不负责直接写代码。  
在以下分歧点上，请产出明确方案决策，并同步给用户协调。

## 2. 已确认问题

- `ASK` 被判成 `AM`
- `PSK` 被判成 `FM`
- `CW / AM / FM / FSK` 当前批次可用
- `sigdet` 日志证据不足

## 3. 你要决策的事项

### 3.1 ASK 方案选择

#### 方案 A：最小改动阈值法

- 取消 `env_level_count <= 4` 的主导地位
- 改用 `env + edge + freq` 组合判断 ASK
- 建议起始门限：
  - `env > 350`
  - `edge > 40`
  - `freq > 80`

#### 方案 B：特征替换法

- 新增：
  - `env_low_ratio`
  - `env_high_ratio`
  - `edge_burst_density`
- 用包络占空特征替代 `env_level_count`

#### 建议

- 若目标是“先跑通”：选 A
- 若目标是“长期稳态”：选 B

### 3.2 PSK 方案选择

#### 方案 A：仅降阈值

- 把 `APP_MODDET_PSK_JUMP_PM_THRESHOLD` 从 `35` 下调到 `15`
- 备选试验值：`12 / 18`

#### 方案 B：联合判据

- `psk_jump_pm >= 15`
- `hist_peak_count == 1`
- `positive_freq_percent >= 85`
- `negative_freq_percent <= 15`
- `env < 200`

#### 方案 C：块级相位跳变检测

- 从相邻采样点判别改为块级相位跳变簇检测

#### 建议

- 若目标是“本轮快速修正”：选 B
- 若目标是“后续竞赛稳定性”：规划 C

### 3.3 sigdet 日志方案选择

#### 方案 A：补最终锁定日志

- 只要求输出最终 `lock` 结果

#### 方案 B：补完整 VPP 扫频日志

- 输出 `coarse/fine` 全过程 `vpp` 数据

#### 建议

- 本轮至少做 A
- 若串口带宽和分析效率允许，再做 B
