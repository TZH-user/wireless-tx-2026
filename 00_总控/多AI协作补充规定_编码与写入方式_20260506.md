# 多 AI 协作补充规定：编码与写入方式（2026-05-06）

本规定用于避免中文文件在多个 AI、PowerShell、VSCode、脚本之间传递时变成乱码。所有参与本项目的 AI 后续必须遵守。

## 1. 总体结论

统一规则：

- 中文 Markdown 协作文件：使用 `UTF-8 with BOM`
- C / H / CMake / JSON / 脚本代码文件：使用 `UTF-8 no BOM`
- 代码注释：优先 ASCII；若必须写中文，确认原文件本来就是 UTF-8 且 VSCode 显示正常
- PowerShell 读取中文文件：必须显式指定 `-Encoding UTF8`
- 不允许用系统默认编码写中文文件

## 2. 为什么这样规定

当前乱码主要来自 Windows PowerShell 5.1、终端代码页、无 BOM UTF-8 文件之间的识别不一致。

中文协作文档需要被不同 AI、PowerShell、VSCode、人类直接打开，因此采用 `UTF-8 with BOM` 更稳。

代码文件需要给 GCC / CMake / STM32 工具链处理，因此采用 `UTF-8 no BOM`，并尽量不写中文注释，避免编译链或日志解析受影响。

## 3. 文件类型规则

### 3.1 Markdown 协作文件

适用：

- `00_调度书.md`
- `00_发给方案决策AI.md`
- `01_方案决策AI输出.md`
- `文件改动记录.md`
- `方案改动记录.md`
- 各 AI 输入输出说明

要求：

- 编码：`UTF-8 with BOM`
- 换行：`CRLF` 或 `LF` 均可，但同一文件内保持一致
- 写入后必须用 VSCode 或显式 UTF-8 读取确认中文正常

PowerShell 读取示例：

```powershell
Get-Content -LiteralPath "文件路径.md" -Encoding UTF8
```

PowerShell 写入示例：

```powershell
Set-Content -LiteralPath "文件路径.md" -Encoding UTF8 -Value $text
```

注意：

- Windows PowerShell 5.1 的 `-Encoding UTF8` 会写入 BOM，适合本项目的中文 Markdown 协作文件。
- PowerShell 7 若要写 BOM，应显式使用 `-Encoding utf8BOM`。

### 3.2 C / H 源码文件

适用：

- `.c`
- `.h`
- `.s`
- `.ld`

要求：

- 编码：`UTF-8 no BOM`
- 新增注释优先使用英文或 ASCII
- 不要批量改动已有注释编码
- 不要为了修注释乱码而碰业务逻辑
- 若文件已有中文乱码，除非任务明确要求修复，否则保持不动，避免扩大改动范围

### 3.3 JSON / CMake / 配置文件

适用：

- `.json`
- `.cmake`
- `CMakeLists.txt`
- `.ioc`
- `.yml`
- `.yaml`

要求：

- 编码：`UTF-8 no BOM`
- 尽量避免中文字段或中文注释
- 写入后确认工具链能解析

### 3.4 日志与采集数据

适用：

- `.log`
- `.txt`
- `.jsonl`
- `.csv`

要求：

- 原始日志保持采集工具输出，不随意重写
- 派生分析文件使用 `UTF-8 with BOM`
- 数据分析 AI 必须说明读取编码

## 4. AI 写入方式约束

### 4.1 文档类文件

推荐：

- 使用编辑器或明确 UTF-8 BOM 的写入方式
- 写入后立即用 `Get-Content -Encoding UTF8` 验证

禁止：

- 用未指定编码的 `Set-Content`
- 用未指定编码的重定向 `>`
- 用默认编码写中文

### 4.2 代码类文件

推荐：

- 使用补丁方式最小改动
- 保持原文件编码风格
- 不引入中文注释，除非用户明确要求

禁止：

- 为了修复文档乱码而批量重写源码
- 把 Markdown 的 UTF-8 BOM 规则套用到 C/H 源码

## 5. 读取方式约束

所有 AI 在读取中文 Markdown 时，应使用显式 UTF-8。

PowerShell 示例：

```powershell
Get-Content -LiteralPath "D:\CodexProject\2026年校电赛\某文件.md" -Encoding UTF8
```

若看到类似 `鍙傛暟`、`璋冨害`、`绠楁硶` 这类乱码，不要直接基于乱码内容决策，应重新按 UTF-8 读取。

## 6. 文件损坏处理规则

若发现文件已经乱码：

1. 先确认它是否只是读取方式错误。
2. 用 VSCode 以 UTF-8 打开确认。
3. 若 UTF-8 读取正常，则不需要修文件，只修读取方式。
4. 若文件本体已经被错误编码覆盖，则先备份乱码文件。
5. 再根据最近的正确版本或上下文重建。
6. 重建后记录到 `文件改动记录.md`。

## 7. 给其他 AI 的强制提示

后续每次分发给其他 AI 时，应附带这句话：

```text
中文 Markdown 协作文件统一使用 UTF-8 with BOM；C/H/工程源码统一 UTF-8 no BOM 且尽量 ASCII 注释。读取中文 Markdown 时必须显式按 UTF-8，不要用默认编码。
```
